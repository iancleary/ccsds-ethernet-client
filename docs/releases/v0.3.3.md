# v0.3.3

- Reuse a bounded transmit frame buffer in the Linux transport, removing one
  allocation per successful send after opening the transport.
- Preserve Ethernet/IP/UDP bytes, checksum defaults, public APIs, and single-send
  behavior. Initialize every transmitted byte, including reused padding.
- Verify changing payload sizes, both IP families, all IPv4 checksum policies,
  and a valid send after oversized input is rejected.

Five alternating trials per version of two complete virtual-link workloads
measured 9,000 to 6,000 process-wide allocation calls for 1,000 commands with
ACKs and telemetry. This is a one-third reduction for those workloads. CPU and
latency ranges overlap; no general throughput improvement is claimed. The
transport reserves 2 KiB per endpoint before measurement begins.

The receive-path evaluation retains the current implementation. Filtering,
statistics sampling, receive batching, and packet mmap can be reconsidered when
their documented evidence criteria are met. See `docs/performance.md`.
