# v0.3.0

## Compatibility

This is a pre-1.0 minor release. Update exhaustive Rust matches for the new
`TransportError::Io` and `EthernetError::MissingIpv4UdpChecksum` variants.
Rust and Python share version 0.3.0.

The default IPv4 transmit checksum remains zero for compatibility. Opt into
`Generate` or `Require` only after checking peer support. The original Python
`RawEthernetClient` still requires serialized access.

## Changes

- Preserve buffered packets before draining the socket. A full transport ring
  no longer discards a later acknowledgement during a telemetry burst.
- Retain session counters for decode failures, ignored messages, unmatched
  acknowledgements, and foreign senders, including after failed exchanges.
- Preserve operation, error kind, and OS error evidence in Rust and Python.
  A statistics refresh failure does not invalidate received packets.
- Reject and count truncated frames and VLAN frames, including stripped tags
  reported through Linux packet metadata.
- Document correlation freshness, acknowledgement stages, and explicit
  recovery. Reject stale interface bindings and clear readiness on failed
  revalidation. Never resend a command implicitly.
- Add optional `ThreadedRawEthernetClient` with one native owner, bounded
  queues, concurrent send/receive, receive cancellation, and joined close.
- Add isolated Linux packet-socket regressions, native installed-wheel checks,
  Rust 1.85 checks, and bounded IPv4/IPv6 parser fuzzing.

## Evidence and limits

Local verification includes `just check`, crate packaging, native AArch64
Linux packet-socket and installed-wheel tests, Rust 1.85 checks with and without
Python bindings, and a sanitizer-enabled parser fuzz smoke run.

Representative performance measurements and physical-peer checksum
compatibility remain separate qualification work. Kernel filtering, further
batching, and packet mmap remain gated on comparative evidence. The virtual-link
benchmark is not a physical-link performance claim.
